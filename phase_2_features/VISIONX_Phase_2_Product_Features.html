VISIONX — Phase 2: Product Feature Implementation

Three domain modules, robust edge integration, alerts, evidence, dashboard and reporting.

Phase Objective

Reuse the Phase-1 common perception engine and build domain intelligence as independent modules. The ESP32-S3 becomes the real camera node while the laptop remains the AI processing platform.

Stage 1 — Production-Style Software Architecture

  1. Define module interfaces between perception and domain logic.
  2. Define configuration files for camera, zones, thresholds and mode.
  3. Separate configuration from source code.
  4. Implement structured logging.
  5. Implement application startup/shutdown lifecycle.
  6. Add error handling around camera, network, inference, DB and storage.
Documents: Software Architecture Specification, module interface specification, configuration reference.

Stage 5 — ESP32-S3 Production Integration

  1. Replace laptop webcam with ESP32 stream.
  2. Run at selected resolution/FPS.
  3. Measure end-to-end capture-to-AI latency.
  4. Add reconnect and timeout handling.
  5. Handle missing frames without crashing inference.
  6. Monitor ESP32 memory and frame-buffer behavior.
  7. Test SD access while camera/Wi-Fi operate.
  8. Test long-duration thermal/power behavior.
Gate: Network performance must be measured under realistic Wi-Fi conditions. If bandwidth is insufficient, reduce resolution/FPS/quality or redesign transport rather than pretending performance is acceptable.

Stage 6 — Alert & Evidence Pipeline

Implement:

Confirmed Critical Event → Event Manager → ESP32 command → Buzzer/GSM → Evidence
  • Define alert command format.
  • Implement buzzer control.
  • Integrate GSM only after basic alert path works.
  • Store important frames/short event clips on ESP32 SD where technically feasible.
  • Keep continuous full video on laptop.
  • Store evidence paths and hashes/identifiers in database if useful.
  • Add alert acknowledgement/status.
