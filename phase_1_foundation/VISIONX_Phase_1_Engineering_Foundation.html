VISIONX — Phase 1: Engineering Foundation

Hardware bring-up, firmware foundation, communications, laptop software foundation and common AI core.

PHASE OBJECTIVE

Build and prove every foundation subsystem independently

Do not begin with the three domains. First establish a stable ESP32-S3 camera node, reliable laptop video pipeline, common detection/tracking engine, storage, database and basic dashboard.

Stage 1 — Requirements & Engineering Freeze

StepImplementationDocumentation / EvidenceAcceptance
1.1Freeze three operating modes and core use cases.Software Requirements Specification (SRS).Every major feature has a defined input, output and limitation.
1.2Define system boundaries: ESP32 handles capture/transport; laptop handles heavy AI.System boundary document.No large AI workload incorrectly assigned to ESP32.
1.3Define measurable targets: resolution, target FPS, latency, detection confidence, recording duration, recovery behavior.Performance target sheet.Targets are measurable, not vague.
1.4Define Normal/Warning/Critical event levels.Event specification.Severity rules are unambiguous.
1.5Create risk register.Risk register with mitigation.Bandwidth, thermal, storage, false alarms and integration risks are listed.
Gate 1: Requirements and measurable acceptance criteria approved before coding major features.

Stage 4 — ESP32 → Laptop Communication

  1. Choose a simple frame transport protocol suitable for the prototype.
  2. Define packet/frame boundaries, sequence number and timestamp.
  3. Implement JPEG transmission.
  4. Implement laptop receiver.
  5. Measure resolution, average JPEG size, FPS, bandwidth and latency.
  6. Test packet loss/disconnection and automatic reconnect.
  7. Define behavior when frames arrive late or out of order.
Documentation: Communication Protocol Specification, message format, timing diagram, bandwidth/latency test report.

Stage 6 — Common AI Perception

  1. Integrate YOLO detection.
  2. Define supported classes for VISIONX.
  3. Measure inference FPS and GPU/CPU memory.
  4. Add confidence and class filtering.
  5. Add multi-object tracking with persistent IDs.
  6. Maintain trajectory history per track.
  7. Handle track creation/loss/re-identification behavior.
  8. Expose detections and tracks to downstream domain modules through a clean interface.
Gate 3: The same perception API must work with webcam and recorded videos and must not contain classroom/traffic/patient-specific logic.

Stage 7 — Spatial & Temporal Foundation

  • ROI/zone representation.
  • Point-in-polygon checks.
  • Virtual line crossing.
  • Direction estimation.
  • Dwell-time calculation.
  • Trajectory smoothing.
  • Frame/time window management.

Stage 8 — Event Engine Foundation

  • Create generic event object: ID, type, severity, timestamp, track IDs, location, confidence, evidence path.
  • Implement multi-frame validation.
  • Add cooldown/de-duplication.
  • Add event state transitions: detected → validating → confirmed → closed.
  • Trigger evidence capture for confirmed important events.

Stage 9 — Basic Dashboard

  • Live video.
  • Bounding boxes and tracking IDs.
  • FPS/latency/network status.
  • Current mode.
  • Event list with severity.
  • Basic event history.
